Container Error Check

Container in error? Upload je exports en de tool spoort automatisch de gekende oorzaken op: duplicate references, vervallen batches, batches zonder datum, overdelivery, open SO / crossdock en deadlocks. Groeit mee met elke nieuwe foutsoort die je tegenkomt.

🧭 Waar ga ik kijken? — vaste zoekroutine (ook zonder exports)
  1. Lees eerst de foutmelding — Licenseplate receiving sessions → container met status Errored → open de log (integrationlog). Kies de melding hieronder bij "Welke foutmelding?" zodat de tool gericht zoekt.
  2. Deadlock (PurchTableVersion)? → stop met zoeken: geen datafout. Reset status + opnieuw proberen, klaar.
  3. "Ordered reserved inventory exists"? → er is een reservering tegen de inkomende (ordered) voorraad — bijna altijd een open SO. Ga naar de SO-regel → Inventory → Reservation → verwijder de reservering (of handel de SO af). Upload export 1 + 3 en de tool wijst het item + de SO aan.
  4. "Cannot edit a record in Load details (WHSLoadLine)"? → procesfout, geen datafout. Vaak na het verwijderen van LP's of door een wave. All work → filter op de wave/load uit de log → Cancel work → check Load details → reset + retry.
  5. "Work has been created"? Kijk in deze volgorde:
    • All work → filter op load-/shipmentnummer → Cancel work (staat het In process: load splitsen).
    • Kolom Work created quantity in het Items-scherm van de sessie toont meteen wélke regel het werk heeft — zit ook in export 1, de tool vlagt het automatisch.
    • Dubbele referenties → upload export 1 hieronder, de tool vindt ze meteen.
    • Marking → PO-regel → Inventory → Marking → verwijderen.
    • Open SO / crossdock op een container-item → upload export 3, de tool checkt het.
  6. Batch-fout? → formaat [land][JJJJMMDD]: vervallen (datum ≤ vandaag), enkel landcode (bv. DE) of leeg. Export 1 uploaden = automatisch gevonden.
  7. Overdelivery? → geleverde hoeveelheid vs. Deliver remainder — upload export 2 voor het exacte %.
  8. Fout stuk gevonden? → verwijder die regel uit de container → reset containerstatus → retry. De rest van de container kan gewoon uitgepakt worden.
  9. Niets gevonden en blijft het foutlopen? → stop met zoeken in de data. Lukt manueel ontvangen zonder fout, dan is de data OK en is de sessie zelf corrupt — volg de escalatieladder onderaan.

Geen bestand geladen
  1. Open de Licenseplate receiving sessions → zoek de container met status Errored.
  2. Open de sessie → Packaging structure details → tabblad Items.
  3. Klik rechtsboven op Options → Export to Excel (of het Excel-icoon op het grid).
  4. Alternatief (nog krachtiger): open de table browser — jullie omgevings-URL + &mi=CgkTableBrowser → tabel WHSLoadLine → filter op LoadId → Export to Excel. Die export bevat WorkCreatedQty: de tool ziet dan meteen welke regels vastgepind zijn door werk.

Zonder dit bestand: geen exact overdelivery-%
  1. Open de inquiry Open purchase order lines. De PO-nummers en item numbers van de container staan hier al automatisch ingevuld — dat doet het scherm zelf, die hoef je niet in te typen.
  2. Ga naar Modify → Filter en controleer dat deze ranges staan: Overdelivery = 10, Type = Purchase order, Line status = Open order, Purchase order status = Open order.
  3. Voer uit → klik Options → Export to Excel.

⚠ Integrationlog: "work has been created" / dimensions cannot be changed
Foutmelding (LP Receiving process V2, srvazr_clips): "Warning/Error — The inventory dimensions on load lines cannot be changed because work has been created. Update has been canceled." Betekent dat iets de voorraad vastpint. Loop deze checklist af:
  1. Duplicate references — meerdere LP's naar dezelfde besteloregel (zie check hierboven).
  2. Bestaand werk — All work → filter op het load-/shipmentnummer → Cancel work (staat het op In process, dan enkel de load splitsen).
  3. Marking — PO-regel → Inventory → Marking tegen een SO/RMA? Verwijder de marking.
  4. Open sales order / crossdock — een open SO op een container-item pint de inbound (zie de crossdock-check). Handel de SO af of annuleer het werk.
Daarna telkens: reset status en herstart het receiving.
⚠ Foutmelding: "Cannot change dimensions because ordered reserved inventory exists"
Er bestaat een reservering tegen de bestelde (ordered) voorraad van een container-item — meestal een open sales order die al gereserveerd heeft op de inkomende PO. Daardoor mogen de dimensies bij receiving niet meer wijzigen.
  1. Vind het item — upload export 1 + 3 hierboven en kies deze foutmelding; de tool wijst het item en de open SO aan.
  2. Verwijder de reservering — SO-regel → Inventory → Reservation → reservering weghalen (of handel de SO af).
  3. Check ook marking op de PO-regel.
  4. Daarna: fout stuk eruit indien nodig → reset status → retry.
ℹ Andere foutmelding: Deadlock op Purchase order versions
Zie je "Cannot edit a record in Purchase order versions (PurchTableVersion) — Deadlock"? Dat is geen container-inhoudsprobleem — zoek er dus niet voor in de export. Het is een tijdelijke database-lock, meestal doordat een batchjob (bv. CLIPS / srvazr_clips) en een gebruiker tegelijk aan dezelfde PO werken.
Oplossing: zet de order-status terug (reset status) of probeer de actie opnieuw — dan is het opgelost. Blijft het terugkomen op dezelfde PO, meld het.
ℹ Foutmelding: "Cannot edit a record in Load details (WHSLoadLine) — The record has never been selected"
Proces-/timingfout, geen datafout in de container-inhoud. Komt vaak nadat je regels uit de container verwijderde: het receiving-proces of een wave verwijst nog naar de oude load-regels.
  1. Staat er een Wave in de log (bv. WAVE-003633148)? → All work → filter op die wave/load → Cancel work.
  2. Check Load details: zijn de verwijderde LP-regels er echt uit?
  3. Reset status → retry. Meestal in 1–2 pogingen opgelost.
Zie je er ook "Some quantity for item ... was not released because not all above location dimensions are known" bij? Zelfde wave-probleem — verdwijnt meestal mee na cancel work + reset.
🪣 Escalatieladder — als je de oorzaak niet vindt
Belangrijk inzicht: lukt manueel ontvangen zónder foutmelding, dan is de data in orde en zit de fout in de receiving-sessie/load zelf (corrupte status, bv. na een wave of het verwijderen van regels). Dan vind je in de exports niets — hoe lang je ook zoekt. Dat is geen falen: stoppen met zoeken is dan de juiste beslissing.
  1. Cancel al het werk van de wave/load (All work) → reset → retry. Max 2 pogingen.
  2. Kijk in WHSLoadLine via de table browser (omgevings-URL + &mi=CgkTableBrowser, filter op LoadId): staan er spookregels van verwijderde LP's? WorkCreatedQty > 0 op veel regels = de load zit massaal vast. Exporteer en gooi in vak 1 — de tool leest het rechtstreeks.
  3. Nog fout? Toont de sessie oude/verwijderde regels → verwijder de receiving-sessie en start een nieuwe voor de container.
  4. Deadline of xdock-stukken nodig? → ontvang manueel. Tijdrovend, maar werkt vrijwel altijd zonder fouten — de snelste betrouwbare uitweg.
  5. Allerlaatste noodgreep: voorraad ophogen via cycle count / adjustment in — enkel als zelfs manueel ontvangen niet lukt en er een deadline op staat. Let op: de PO blijft open (factuurcontrole breekt), risico op dubbele voorraad als de vastzittende regel later alsnog verwerkt wordt, en batch/serienummer moet je zelf correct zetten. Altijd melden aan admin/IT + achteraf rechtzetten.
  6. Noteer sessie-ID + wave-nummer + PO's en meld het aan IT/CLIPS-beheer: een sessie die na cancel + reset blijft foutlopen is een procesbug, geen gebruikersfout.
Pre-check tip: containers met xdock-items (open SO) zijn gevoelig voor dit alles. Haal export 1 + 3 door de tool vóór je begint met ontvangen: licht "Open SO / crossdock" op, verwacht dan waves/werk en check eerst de reserveringen.
Duplicate references — meerdere license plates die naar dezelfde besteloregel wijzen. Vaak de oorzaak van "inventory dimensions on load lines cannot be changed because work has been created".
Batch vervallen — batchnummer met formaat [land][JJJJMMDD] waarvan de datum vandaag of eerder is (bv. DE20260630 op 1/07/2026). Komt al over datum binnen → error.
Batch zonder datum — batch bevat enkel een landcode (bv. DE, AT) zonder datumcijfers, of is helemaal leeg terwijl hetzelfde item elders wél een batch heeft.
Overdelivery — hoeveelheid boven de tolerantie t.o.v. Deliver remainder op de open PO-regel.
Alles draait lokaal in je browser — er wordt niets geüpload naar een server.
